# QuFoods Data Intelligence Platform

A full data engineering pipeline and reporting application built for QuFoods — 
a quick-service restaurant chain operating 20 branches across Nigeria.

Built by the Qucoon team as part of an AWS Partner SOW engagement.

---

## What This Project Does

Raw transaction data from all 20 QuFoods branches lands in an AWS S3 bucket 
every few minutes. This pipeline:

1. Cleans and validates the raw data — fixing misspelled menu items, 
   recovering missing branch names, and imputing missing transaction amounts
2. Loads the cleaned data into a Neon PostgreSQL analytics database
3. Serves a Streamlit reporting application that generates PDF reports 
   and AI-powered narrative summaries for three management audiences

## How to Run

### Step 1 — Clone the repository

```bash
git clone <your-repo-url>
cd qufoods_app
```

### Step 2 — Set up a virtual environment

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Mac/Linux
```

### Step 3 — Install dependencies

```bash
pip install -r requirements.txt
```

### Step 4 — Set up AWS credentials

Create `.streamlit/secrets.toml` with your AWS credentials:

```toml
[aws]
access_key_id = "YOUR_ACCESS_KEY_ID_HERE"
secret_access_key = "YOUR_SECRET_ACCESS_KEY_HERE"
```

This file is in `.gitignore` and must never be committed to the repository.
The credentials need the following AWS permissions:
- `s3:GetObject` and `s3:ListBucket` on the `qufoods-raw` bucket
- `bedrock:InvokeModel` for AI narrative generation

### Step 5 — Run the app

```bash
streamlit run app.py
```

The app opens automatically at `http://localhost:8501`

## Connecting to the Live Database

The app currently loads data from a local fallback JSON file when S3 is 
unreachable. When the live Neon PostgreSQL database is ready:

1. Open `db.py`
2. Add the Neon connection string:

```python
CONNECTION_STRING = "postgresql://user:password@host/dbname?sslmode=require"
```

3. Switch `get_sales()` and `get_expenses()` to use the SQL queries 
   provided in `db.py` comments
4. Update `top_ordered_items()` in `queries.py` to use `get_top_items()`
   — see the comment in that function for instructions

No other changes are needed. All charts, metrics, PDFs, and AI summaries 
update automatically.

## Amazon Bedrock AI Summaries

Each report has a **✨ Generate AI Summary** button that calls Amazon Bedrock 
to produce a plain English narrative of the report metrics.

**Model used:** `us.anthropic.claude-haiku-4-5-20251001-v1:0`  
**Region:** `us-east-1`  
**Approximate cost:** ~$0.0003 per summary

The Bedrock call is non-blocking — if it fails or times out the report 
continues to function normally without the narrative.

To enable Bedrock:
- Ensure your AWS credentials have `bedrock:InvokeModel` permission
- Request model access for `claude-haiku` in the AWS Bedrock console
- Credentials go in `.streamlit/secrets.toml` as shown above

## Pipeline Architecture

S3 (Raw) — qufoods-raw bucket, us-east-1
│
│ EventBridge — triggers every 5 minutes
▼
AWS Lambda (Clean + Validate)
│ - Fixes misspelled menu item names (fuzzy match, 75% threshold)
│ - Recovers null branch names from branch registry
│ - Imputes missing total_amount values (algebraic or regression)
│ - Separates sales and expense records
▼
S3 (Processed) — audit copy of cleaned records
│
▼
Neon PostgreSQL (Gold Layer) — analytics-ready database
│
▼
Streamlit Reporting App
│
├── Branch Performance Report (daily, green theme)
├── Regional Comparison Report (weekly, red theme)
└── Operations Report (monthly, blue theme)
│
▼
PDF Export + AI Narrative (Amazon Bedrock)

## Report Types

### Branch Performance Report
For branch managers. Daily view showing:
- Total revenue, transactions, average order value, failed transaction rate
- Revenue by branch, payment method split, top ordered items
- AI-generated narrative summary
- Downloadable PDF

### Regional Comparison Report
For regional managers. Weekly view showing:
- Revenue vs expenses by branch
- Top and lowest performing branch
- Loyalty membership penetration per branch
- AI-generated narrative summary
- Downloadable PDF

### Operations Report
For the Head of Operations. Network-wide view showing:
- Total network revenue vs total expenses
- Top 5 and bottom 5 branches by revenue
- Network-wide transaction status breakdown
- AI-generated narrative summary
- Downloadable PDF

All reports support:
- Branch filter — drill into a single branch
- Time period selector — All, Today, 1W, 1M, 3M
- Chart type switcher — Bar, Line, or Pie on every chart

## Data Quality Handling

| Issue | Resolution |
|---|---|
| Misspelled menu item names | Fuzzy match correction at 75% confidence threshold |
| Null branch names | Deterministic lookup against branch registry using branch_id |
| Missing total_amount | Algebraic imputation or regression fallback |
| FAILED transactions carrying total_amount | Filtered out of all revenue calculations |
| Negative dwell times | Excluded from dwell time metrics |
| Imputation formula error in brief | Corrected to multiplicative formula — total = subtotal × (1 - discount) |

---

## Key Business Rules

- Revenue always filters `transaction_status = 'COMPLETED'` only
- `discount_applied` is a rate (0.12 = 12% off), never a currency amount
- Reports are generated on demand, not as live dashboards
- Bedrock narrative is optional — reports work fully without it
- Never commit credentials to this repository
